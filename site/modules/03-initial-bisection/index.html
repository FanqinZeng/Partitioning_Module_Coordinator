03 / BEFORE YOU READ

先认识这些词

组队先抽签，还是先找合作最多的人？

构造 / construction

从没有分组开始建立分组。

种子 / seed

控制伪随机序列的整数。

增量 / increment

当前决定对已分配节点造成的新跨边代价。

区域生长 / region growing

从一个锚点逐步吸收连接最强的未选节点。

平票 / tie

分数相等时采用预先声明的确定性规则。

01 · 构造一个起点

初始二分回答“从哪里开始”。它从图和明确的人数目标出发，给所有节点贴上 0 或 1 的标签。KL/FM 则从已有分组出发尝试改进。不要把构造中的临时状态，当成改进算法每一步都必须满足的最终解。

本章统一要求最终人数为 floor(n/2) 与 ceil(n/2)，面积只作诊断。三种方法共享这个输出契约，但过程不同。锚点取按名称排序后的第一个节点；图中平票按名字处理。算法简单，规则却需要写全，才能复现实验。

02 · 有种子的随机基线

随机法先用整数 seed 产生一个确定的伪随机序列，再用 Fisher–Yates 洗牌。洗牌后前 floor(n/2) 个节点去左侧，其余去右侧。它不是逐点抛硬币，因此不会随机产生空侧或违反最终人数目标。

同一个输入、同一个种子和同一个伪随机生成器产生同一结果。仅说“seed=7”还不足以跨语言复现；必须连生成器与洗牌规则一起说明。本课程浏览器使用 mulberry32，Python 小实验聚焦确定性生长，不假定 Python random 与 JavaScript 等价。

随机法适合作为基线，也可运行多个种子比较结果分布。只挑出最好的那一次却不报告尝试次数，会高估它的稳定性。它没有看边权，因而没有理由保证割代价较小。

03 · 顺序贪心的增量

贪心法先把锚点放左，再按名字处理其他节点。对当前节点 v，分别计算它放入左右侧时，与已分配节点之间新增的跨边权重。超过目标人数的侧先排除，然后选择增量更小的合法侧；增量相同优先当前人数较少的一侧，再取较小组号。

公共图从 A 在左开始。处理 B 时，放左新增 0，放右新增 5，因此 B 去左；左侧目标人数 2 已满，C、D、E 随后必须去右。最终 AB | CDE 的 cut 为 AC+BC=5。这个局部选择没有保证后面的连接也好。

实验台的候选表给出当前决定使用的增量，图上的总 cut 则按一个完整临时标签计算。贪心尚未处理的节点暂画在右侧；事件中的 placed 清单明确指出哪些节点已参与本次增量评分。不要把临时图的 cut 与候选增量混为一谈。

04 · 区域生长

生长法也从 A 出发，但下一步不按名字固定处理节点。它给每个未加入左侧的节点打分：该节点与当前左侧所有节点的边权之和。取最高分，平票取名字小的节点，直到左侧有 floor(n/2) 个节点；其余统一去右。

G01 第一步的候选分数为 B:5、C:1、D:0、E:0，因此吸收 B 后停止，仍得到 AB | CDE，cut=5。它与顺序贪心在这张图上相同，不表示两个算法相同。换一张图或改变锚点，选点顺序可能明显不同。

05 · 把平票和容量写进算法

“把联系最紧的点放一起”不是可执行规格：联系指单条边、总和还是平均？吸收左侧还是两侧轮流？满了以后怎么办？一个平票会改变之后所有候选分数，因此规则不是无关紧要的细节。

当节点面积不相等，人数目标仍然不会自动保证面积平衡。若你要把本章改成面积容量构造器，需要重新定义合法候选与无法继续时的状态，不能只把显示标签从“人数”换成“面积”。

06 · 比较起点的方式

先固定图、节点顺序、人数目标和平票规则，再比较 cut。随机方法还需记录种子与运行次数。然后将各起点送入同一个改进器，观察最终 cut 和改进路径；这能区分“起点本身好”与“起点容易被后续方法修好”。

本课程的比较页使用相同 G01，并在每行显示方法的约束。相同结果只支持这个具体样例的结论。想比较稳定性，需要一组有代表性的图、明确的预算和每次运行的完整记录。

07 · 实现与检查

Python 区实现 grow_order 和 balanced_initial：前者返回从锚点开始的完整生长顺序，后者按给定顺序取前 floor(n/2) 个节点作为左侧。检查包括平票、断连图、奇偶节点数和不重复不遗漏。

本章停止条件是达到指定人数，或所有节点已处理。它不会因为当前 cut 不再下降就提前停止。下一章将在完整分组上计算成对交换增益，保留本章输出作为可复现的起点。

08 / COMMON MISTAKES

这些结论需要再想一步

随机等于不可复现

固定生成器、种子和洗牌规则可以复现。

生长与顺序贪心完全相同

两者在 G01 得到同样 cut=5，但前者选择下一个节点，后者按固定顺序放置。

容量只在最后检查

顺序贪心先过滤满侧，才能保证目标人数。

起点合法就最优

默认起点 cut=5，ABC | DE 可做到 3。
