03 / BEFORE YOU READ

先认识这些词

挪动一对座位，为什么要先试完再决定保留哪几步？

D 值 / D value

节点跨组边权减同组边权。

增益 / gain

cut_before − cut_after，正数表示改进。

锁定 / lock

本 pass 中不再选择已试探的节点。

pass

从初始状态开始，选择互不重复的候选直到无法继续。

最佳前缀 / best prefix

累计增益最大的最早前缀，允许空前缀。

01 · 用一对交换保持人数

KL 从一个完整二分出发，每次从两侧各选一个未锁定节点交换。因此两侧节点数始终不变，但面积可能改变。公共图起点 AE | BCD 的 cut 为 12；想知道哪一对值得交换，先把每个节点对 cut 的局部影响算清楚。

外部边是通向异侧的边，内部边通向同侧。定义 D(v)=external(v)−internal(v)。若只移动一个节点，这就是 cut 的下降量，但 KL 同时移动两个节点，不能直接把两个 D 相加。

02 · 成对增益为何要减两次边权

交换异侧 a、b 的增益为 g(a,b)=D(a)+D(b)−2w(a,b)。若两点之间没有边，w=0。直接相加两个 D 时，a–b 这条原本跨组的边会被当成两次“移除”；实际交换后它仍然跨组，所以必须减去 2w。

在 AE | BCD 中，D(A)=6，D(E)=6，D(B)=1，D(C)=−2，D(D)=3。候选 A↔D 的增益为 6+3−0=9，交换后得到 DE | ABC，cut=3。请用另一种方法复核：复制分组、实际交换，再计算 cut_before−cut_after，应与公式完全一致。

03 · 锁定不是立即接受

选出最大增益候选后，先在试探分组中交换并锁住两点。本 pass 后续不能再选择它们。然后在新的试探分组上更新 D 值和候选。若多对增益相同，按 a、b 的名称排序；候选的 a 总来自当前 0 侧。

试探过程仍然继续，即便下一步增益为负。公共图第一步增益 9，第二步增益 −8；相应累计增益为 9、1。第二步使 cut 从 3 回升到 11，但这不是最终接受结果。实验台用事件类型明确区分 trial-swap 与 best-prefix。

04 · 最佳前缀与回退

给增益序列 g1…gm 加上空前缀 G0=0，再计算 Gk=Σi≤k gi。选择累计增益最大的最早 k。若最大值不大于 0，就保留空前缀，不改变 pass 起点。不要选择单步增益最大的那一步，也不要只保留所有正增益动作后拼接成一个不存在的过程。

G01 的序列 [9,−8] 对应前缀 [0,9,1]，最佳 k=1。因此从 pass 起点重新执行第一对交换，撤销其后的试探，接受 cut=3。页面的前缀图和当前分组一起回退，避免只更新数值却没恢复标签。

一个更能说明“负增益仍值得试探”的序列是 [−2,5,−1]：最佳前缀长度为 2，总增益为 3。这里第一步必须先变差，后面才可能变好。这个算术例子只解释前缀选择，不冒充 G01 的实际轨迹。

05 · 多个 pass 与停止条件

接受最佳前缀后，解除锁定并从接受分组开始下一个 pass。若下一轮最佳前缀为空，就按“无正累计增益”停止；达到 pass 上限则报告 limit。二者不能都显示为“已找到最优”。

KL 搜索的是特定成对交换与前缀策略能发现的改进，不保证全局最小 cut。即便小图精确枚举与它结果相同，也只能说明这一实例吻合。它还保持初始人数，如果起点人数本来不符合需求，成对交换无法修正人数目标。

06 · 核对实现的四个不变量

每次试探后检查：左右节点数不变；锁定节点不重复；实际 cut 差等于记录增益；累计增益等于 pass 起点 cut 减当前试探 cut。接受前缀后，cut 应等于起点 cut 减最佳累计增益，并且不能高于起点。

repeat a pass:
    trial ← accepted; unlock all
    choose best unlocked cross pair
    swap in trial; lock both; record gain
    repeat until one side has no unlocked vertex
    accept earliest maximum positive prefix
stop when the empty prefix is best

教学引擎每次枚举未锁定跨侧点对并重新计算候选，便于审查。不要把这一实现的运行时间当成所有 KL 工程实现的性能结论。

07 · 与 FM 的关系

KL 与 FM 都有试探、锁定和最佳前缀。差别不是“KL 只接受单步改进，FM 才允许变差”；完整 KL 同样允许负增益试探。主要差别是一次移动的对象、平衡检查和候选维护。

Python 区实现 pair_gain 与 best_prefix。检查会把公式与实际交换后的 cut 比较，并测试空前缀、全负增益和平票时最早前缀。下一章会看到一个收益最高的节点，因为移动后人数不合法而必须等待。
