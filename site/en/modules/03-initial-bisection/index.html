02 / PROBLEM CONTRACT

State the problem first

Input
A small undirected weighted graph with positive vertex areas.
Output
One part label per vertex and a replayable event trace.
Objective
Evaluate or reduce crossing edge weight.
Constraints
Use the declared count/balance contract; report counts and areas separately.
Assumptions
Each edge once, deterministic ties; no physical routing simulation.
Stop
When target counts are reached

03 / BEFORE YOU READ

Terms to know

Should teams start with a draw, or with the strongest collaborators?

构造 / construction

Building an assignment from scratch.

种子 / seed

An integer controlling the pseudorandom sequence.

增量 / increment

The new crossing cost to already assigned nodes.

区域生长 / region growing

Expand an anchored part using connection strength.

平票 / tie

Equal scores resolved by a declared deterministic rule.

01 · Construct a starting point

Initial bisection answers where to start. It builds an assignment from the graph; KL and FM instead refine an existing assignment. Temporary construction states should not be confused with the final contract.

All three methods finish with floor(n/2) vertices on the left and ceil(n/2) on the right. Areas are diagnostics. The first vertex in name order is the anchor and equal scores use name order. These decisions make the simple algorithms reproducible.

02 · A seeded random baseline

The random method uses an integer seed and Fisher–Yates shuffle, then assigns the first floor(n/2) shuffled vertices to the left. Unlike independent coin flips, this guarantees the final counts and avoids empty sides.

Reproducibility requires the generator and shuffle rule as well as the seed. This browser uses mulberry32. The Python exercise focuses on deterministic growing; it does not assume Python random matches JavaScript.

Try several seeds and report the distribution or the number of attempts. Selecting only the best seed without reporting the budget exaggerates reliability. Random construction ignores edge weights, so it has no low-cut guarantee.

03 · Incremental greedy placement

Place the anchor on the left, then process remaining vertices in name order. For each legal side, sum the new crossing weight to already placed vertices. Discard full sides first. Choose smaller increment, then smaller current count, then smaller side number.

In G01, after A goes left, B costs 0 on the left or 5 on the right. B goes left, filling its target of 2. C, D and E must go right. The final cut of AB | CDE is AC+BC=5. The decision was locally sensible, but did not optimize future connections.

The candidate table reports the increment used for selection. The graph shows a complete temporary assignment, drawing unprocessed vertices on the right. The placed list identifies which vertices contributed to the score. A temporary total cut is not the same quantity as a placement increment.

04 · Region growing

Starting at A, growing scores every unselected vertex by its total connection weight to the current left side. Pick the maximum, breaking ties by name, until the left side reaches floor(n/2). All remaining vertices form the right side.

The first G01 scores are B:5, C:1, D:0, E:0. Adding B completes the left side and again gives cut 5. Agreement on this graph does not make growing and sequential greedy the same algorithm. A different graph or anchor can change their orders.

05 · Specify ties and limits

“Keep strongly connected vertices together” is not an executable specification. Does strength mean a single edge, a sum or an average? Which side grows? What happens when it is full? A tie affects later scores and therefore matters.

Unequal areas break the correspondence between count targets and area balance. An area-constrained constructor needs its own candidate rules and failure state. Relabeling a count as an area does not implement that change.

06 · Compare starts fairly

Fix the graph, order, count targets and tie rules. Record seeds and run budgets for random methods. You can then feed the different starts into the same refiner, separating a good initial cut from a starting point that is easy to improve.

The comparison page uses one graph and states every row's contract. An equal result supports only a conclusion about that example. Claims about reliability require a representative graph collection and a declared computational budget.

07 · Implement and check

Implement grow_order to return the full anchored growing order, then balanced_initial to assign its first floor(n/2) vertices left. Tests cover ties, disconnected graphs, odd and even sizes, uniqueness and completeness.

Construction stops when its target count is reached or all vertices have been processed. It does not stop just because the current cut fails to improve. The next lesson computes swap gains on a complete starting assignment.

08 / COMMON MISTAKES

Conclusions to examine carefully

Random means irreproducible

Fix generator, seed and shuffle rule to reproduce.

Growing equals sequential greedy

Both yield 5 here, but growing chooses the next vertex while greedy uses a fixed order.

Check count limits only at the end

Filter full sides before ranking greedy placements.

Legal construction is optimal

The default start costs 5 while ABC | DE costs 3.
